# Changes — 2026-09-10

## 1. User App — FAB buttons (WhatsApp / Telegram) not showing — FIXED (root cause found)
`index.html` was calling `document.getElementById('home-view')` to check whether the Home
tab was active, but the real element is `id="tab-home-view"` — so that lookup always
returned `null` and the show/hide functions silently did nothing. On top of that, the CSS
rule required the buttons to be *descendants* of the home section
(`#home-view.show-fab .fab-whatsapp`), but the buttons are `position:fixed` elements placed
*outside* that section in the markup, so even a correct ID would not have been enough.

Fixed: the buttons now get a `.show` class directly (no dependency on DOM nesting), the ID
lookup is corrected, and visibility is now updated from a single place — inside `navigateTo()`
itself — instead of a "hook" that a later part of the file was silently overwriting.

## 2. User App — Double back-press to exit — FIXED (was never wired to the back button)
The exit-confirmation popup already existed in the HTML, but nothing ever triggered it from
the hardware/browser back button — it was only reachable from an unused code path. Added:
- A history "trap" so the back button doesn't just close the app on Home with nothing to
  go back to.
- First back-press on Home → arms a 2-second window + a small toast hint.
- Second back-press within that window → shows your Yes/No exit popup.
- `exitAppConfirmed()` now tries a few common WebView-wrapper JS bridges
  (`navigator.app.exitApp`, `window.Android.exitApp`, `window.AndroidBridge.exitApp`) before
  falling back to closing the tab.

## 4. User App — Google sign-in stuck after picking an account — Partially addressed
Could not fully root-cause this without being able to test live (see note at the end), but:
- Added much clearer, specific error messages (including the raw Firebase error code) when
  something does fail, instead of one generic message for everything.
- Added a watchdog: if the page returns from Google's sign-in flow with no result and no
  error (exactly your symptom — picked an account, tapped Continue, then nothing), it now
  shows an explicit toast telling you what likely happened, instead of failing silently.
- Skipped the ~4 second splash-screen replay specifically when returning from a Google
  redirect, so a *successful* sign-in doesn't look like it's still stuck.
- **Likely real cause, needs your confirmation:** if the "User app" you're testing this in is
  an installed APK that wraps this website in a generic Android WebView (rather than opened
  directly in Chrome), Google deliberately blocks OAuth sign-in from completing inside plain
  WebViews for security reasons — this is a Google policy restriction, not a bug in this
  code, and it can only be fixed on the native-app side (using Chrome Custom Tabs or a native
  Google Sign-In SDK instead of a plain WebView for that one screen). That native wrapper's
  source isn't in this project zip, so I can't patch it from here. **Please test the "Sign in
  with Google" button by opening the site directly in Chrome** — if it works there but not in
  the installed app, that confirms this is the cause.

## 5. Admin Panel — banner/match "buttons don't work" — one confirmed bug fixed, added diagnostics
Found and fixed one real bug: the Finalize Match modal's "Add placement" button called
`App.addPlacement($(document.getElementById('fin-name').value))` — `$` was never defined
anywhere in the file, so clicking it threw an error every time. Removed the stray `$(...)`.

I reviewed the rest of the banner/match code (every `App.xxx()` call used in the page matches
an actual exported function, the backend routes for both look correct) and couldn't find a
second broken button this way. **If it happens again, you should now see a red error toast
on screen with the exact error text** (previously errors only went to the browser console,
which isn't visible on a phone) — please send me that text and I can fix it precisely instead
of guessing.

## 6. Admin Panel — Upload picture from gallery — ADDED
Every place that only accepted a pasted image URL (Banner image, Category image/icon, Match
icon, and the Media Gallery "add image" box) now also has an **Upload** button next to it.
Picking a photo resizes it in your browser (max 1000px, JPEG ~72% quality) and drops it
straight into the same field as a compact embedded image — no external image host needed.
Backend field-length limits were raised so these uploaded images aren't cut off when saved.
